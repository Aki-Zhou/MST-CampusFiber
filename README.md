# 最小生成树的校园光缆铺设可视化（CampusFiber）

> 数据结构课程设计 —— 用 **Kruskal 算法**求解校园光缆铺设的最小生成树，并以图形界面**逐步演示**算法的每一步决策过程。

给定校园内若干建筑物及其相互之间的距离（铺设成本），如何用最低的总成本把所有建筑用光缆连通？这是一个典型的**最小生成树（Minimum Spanning Tree, MST）**问题。本项目用手写的最小堆和并查集实现 Kruskal 算法，并把「取边 → 判环 → 入树 / 丢弃」的每一步实时画出来。

---

## 效果说明

程序运行时窗口分成绘图区和信息区：节点以圆圈表示，边以直线表示，边的**颜色随算法状态实时变化**。

| 颜色 | 状态 | 含义 |
|:---:|---|---|
| ⚪ 灰色 | `state = 0` | 尚未处理的边 |
| 🟡 黄色 | `state = 1` | 正从最小堆中取出、准备判定 |
| 🟢 绿色 | `state = 2` | 已加入最小生成树（不构成环） |
| 🔴 红色 | `state = 3` | 构成环，被丢弃（短暂显示后恢复灰色） |

右下角信息区实时显示**当前累计成本**和**算法日志**（每一步连接或判环的记录），算法结束后显示最终总成本。

**按 `Enter` 键推进到算法的下一步。** 这是刻意设计的交互方式，方便讲解时逐步演示而不会一闪而过。

## 算法设计

### 用到的数据结构

| 结构 | 位置 | 作用 |
|---|---|---|
| **最小堆** `MinHeap` | [runtime/DataStructure.h](runtime/DataStructure.h) | 按边权从小到大取出边，避免每轮全量排序 |
| **并查集** `UnionFind` | [runtime/DataStructure.h](runtime/DataStructure.h) | 判断一条边的两个端点是否已连通，即是否成环 |
| **节点/边数组** `Node` / `Edge` | [runtime/DataStructure.h](runtime/DataStructure.h) | 存储图的静态数据；`Edge::state` 驱动上面的颜色变化 |

- **最小堆**为手写的二叉堆，用数组存储，`Push` 时上浮、`Pop` 时把末尾元素移到堆顶再下沉。相比每轮重新排序，把「取最小边」的复杂度从 `O(E log E)` 一次性排序优化为增量的 `O(log E)`。
- **并查集**带**路径压缩**（`find` 递归时把沿途节点直接挂到根上），使判环操作接近常数时间。注意本项目**未使用按秩合并**，合并时固定把前者的根挂到后者根下。

### Kruskal 算法流程

见 [GraphSystem.cpp `runKruskal`](GraphSystem.cpp)：

1. 把全部边压入最小堆；
2. 循环：从堆中弹出**当前权重最小**的边（变黄）；
3. 用并查集 `unite(u, v)` 判断两端点是否已在同一连通分量：
   - **否** → 该边加入 MST（变绿），累计成本，日志记录 `Connect: ...`；
   - **是** → 该边会构成环，丢弃（变红），日志记录 `Cycle: ...`；
4. 直到**已选边数 = 节点数 − 1**（此时必然已连通）或堆为空，算法结束。

> 终止条件 `edgesCount < nodeCount - 1` 是 Kruskal 的关键：n 个节点的生成树恰好有 n−1 条边，选够即可提前退出，无需处理完所有边。

## 快速开始

### 1. 获取代码

```bash
git clone https://github.com/Aki-Zhou/MST-CampusFiber.git
cd MST-CampusFiber
```

### 2. 编译

SFML 依赖**不需要手动安装**，CMake 会自动处理，二选一：

- 若源码树里存在 `libs/SFML-2.6.1/`（本机开发用的完整源码），**直接使用，无需联网**；
- 否则自动通过 `FetchContent` 从 GitHub 下载并编译 SFML 2.6.1。

```bash
cmake -B build -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

Windows + MinGW 请显式指定生成器：

```bash
cmake -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release
cmake --build build -j
```

> **国内网络下载 SFML 慢或失败**时，换用镜像源：
> ```bash
> cmake -B build -DSFML_GIT_REPOSITORY=https://gitee.com/mirrors/SFML.git
> ```

### 3. 运行

```bash
./build/CampusFiber        # Linux / macOS
.\build\CampusFiber.exe    # Windows
```

`font.ttf` 和 `data.txt` 会被 CMake 自动复制到可执行文件所在目录，**务必在该目录下运行**，否则会提示字体加载失败。

## 使用说明

### 三种输入方式

程序启动后显示菜单，输入 `1`／`2`／`3` 选择：

| 选项 | 说明 |
|:---:|---|
| `1` | **随机生成图** —— 随机生成 7 个节点的完全图，坐标为随机分布，边权为 10–109 的随机整数 |
| `2` | **手动输入图** —— 依次输入节点个数（2–20）、每个节点的名称与坐标、边数、每条边的起点/终点/权重 |
| `3` | **从文件加载图** —— 从当前目录的 `data.txt` 读取 |

手动输入模式下**节点编号从 0 开始**，例如 5 个节点的合法编号是 0–4。输入越界或权重非正时程序会提示并让你重新输入。

| 关闭窗口 | 随时退出程序 |

## 数据文件格式

`data.txt` 为纯文本，格式如下：

```
第一行：节点数量 N
随后 N 行：节点名称 X坐标 Y坐标
其余行：起点编号 终点编号 权重
```

仓库自带的示例 [data.txt](data.txt)：

```
8                      ← 8 个节点
A 100 333              ← 节点 0：名称 A，坐标 (100, 333)
B 300 210
C 500 520
D 400 150
E 100 250
F 270 280
G 500 190
H 700 330
0 1 10                 ← 边：A-B，权重 10
1 2 12
3 4 15
0 4 20
1 5 25
2 6 18
3 7 22
4 5 14
5 6 16
6 7 11
1 4 30
5 2 28
```

对该组数据，程序求出的最小生成树为 **A-B(10)、G-H(11)、B-C(12)、E-F(14)、D-E(15)、F-G(16)、C-G(18)**，**总成本 96**，其余边均因成环被丢弃。

> 加载时会校验每条边的端点编号是否落在 `0 ~ N-1` 内、权重是否为正。非法边会被**跳过并打印警告**，而不是默默产生错误结果——见下方「健壮性处理」。

## 健壮性处理

课程设计的原始版本在输入路径上缺少校验，本项目补齐了以下防御：

- **文件加载校验**（`initFromFile`）：逐项检查节点数量是否落在 `1 ~ MAX_Nodes`、节点信息是否完整、每条边的端点是否越界、权重是否为正。非法项被跳过并打印明确警告，文件格式错误则直接返回失败而非继续读取。
  > 这一项修复针对的是一个真实存在过的缺陷：示例数据中曾有一条 `8 9 15`，而文件声明只有 8 个节点（合法编号 0–7）。旧代码不做校验，`find(8)` 会访问未初始化的内存，节点名也会打印成乱码。
- **容量上限显式上报**：最小堆容量为 `MAX_Edges = 100` 条边。旧代码在堆满时**静默丢弃**多余的边，会导致生成树不完整却毫无提示；现在 `Push` 返回是否成功，调用方统计丢弃数量并警告用户。
- **参数范围钳制**（`initRandom`）：节点数被限制在 `2 ~ MAX_Nodes` 之间，避免越界写入 `nodes[]`。
- **手动输入校验**：节点数与边数均有范围检查，边权必须为正。

## 常见问题

### 链接时报 `undefined reference to '_setjmp'`

**MinGW-w64 GCC 13 及以上**会遇到。原因是 SFML 2.6.1 自带的 `extlibs/libfreetype.a` 是多年前用旧版 MinGW 编译的，其中引用了符号 `_setjmp`；而新版 MinGW 的 `setjmp.h` 已改用 `__intrinsic_setjmp` 等内部名字，`libmsvcrt.a` 里**不再导出 `_setjmp`**。

本项目已在 `CMakeLists.txt` 中自动处理：检测到 MinGW 且 `setjmp` 可用时，追加链接器别名

```
-Wl,--defsym=_setjmp=setjmp
```

把旧符号指向仍然存在的 `setjmp`，语义等价。**无需手动干预。**

若仍有问题，另一种方案是改用 CLion 自带的 MinGW（GCC 13，`_setjmp` 尚存）。

### 运行时报 `0xC0000139`（STATUS_ENTRYPOINT_NOT_FOUND）或进程静默退出

**这不是本项目的问题，而是运行时加载到了版本不匹配的 `libstdc++-6.dll`。** 当 PATH 中存在多个 MinGW 时容易发生：可执行文件由 A 版本 GCC 编译，却优先加载了 B 版本的 `libstdc++-6.dll`，导致找不到入口点。

排查方式：

```bash
# 看哪个 libstdc++-6.dll 会最先被加载
for d in $(echo "$PATH" | tr ':' '\n'); do [ -f "$d/libstdc++-6.dll" ] && echo "$d"; done
```

把编译该程序所用的 MinGW 的 `bin` 目录**放到 PATH 最前面**即可：

```bash
export PATH="/d/MinGW/bin:$PATH"
```

想彻底避免这个问题，可以静态链接 C++ 运行库，产出一个不依赖 MinGW DLL 的可执行文件：

```bash
cmake -B build -G "MinGW Makefiles" -DCMAKE_BUILD_TYPE=Release \
      -DCMAKE_EXE_LINKER_FLAGS="-static"
```

### 提示「字体加载失败」

`font.ttf` 没有和可执行文件放在同一目录。CMake 构建时本会自动复制到构建目录，请**在该目录下运行程序**；若手动移动过可执行文件，把 `font.ttf` 一起带上。

### 随机生成图时报「边被丢弃」警告

随机模式生成的是**完全图**，边数为 `C(n,2)`。当节点数超过 14 时 `C(n,2) > 100`，会超出最小堆容量。此时程序会明确警告丢弃了多少条边。把节点数控制在 **14 以内**即可确保结果完整。

## 已知限制

- 最小堆与节点数组容量固定（`MAX_Edges = 100`、`MAX_Nodes = 100`），未做动态扩容。
- 并查集使用路径压缩但**未按秩合并**，最坏情况下比最优实现略慢（对本项目规模无实际影响）。
- 窗口缩放仅触发重绘，未做视图自适应变换，节点坐标不会随窗口比例缩放。
- 日志文本使用固定长度缓冲区（`sprintf`），节点名过长时存在截断风险。
